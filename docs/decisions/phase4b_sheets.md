# 階段 4b 計畫：報表同步到公司 Google Sheet（做法 A）

狀態：**已確認並實作**（2026-10-14，第 6 節五點均照計畫：公司使用 Google Workspace、同意安裝 gspread／google-auth、由公司管理員依 docs/handover/google_sheets.md 設定、試算表含案名與負責人（內部一般）、第一版單向同步。週報另產生結構化資料檔 `管理層週報_資料_日期.json` 供同步讀取）
依據：CLAUDE.md 第 2、7 節（輸出放在使用者已經在用的地方；接 Google Sheets 要先經同意）、docs/manager_questions.md 第 1、5 題
估計時數：6–8 小時（超過 12 小時會停下來回報）

## 1. 要做什麼
每週一鍵執行（`run_weekly.py`）跑完後，**多一步**：把本週結果寫進公司的 Google 試算表，主管用瀏覽器或手機打開就能看、能篩選。

- 原本的 Excel、Word、郵件版**照樣產生**，同步只是多一個出口。
- **單向同步**：系統只寫入、不從試算表讀回（第一版）。
- 同步失敗不影響本機報表，執行結果會明確寫「Google 試算表同步失敗：原因」。

## 2. 試算表長什麼樣子
建議一份試算表「管理層系統」，分頁如下（每週覆蓋成最新一份，另留一頁歷史）：

| 分頁 | 內容 | 來源 |
|---|---|---|
| 週報 | 本週結論三句、關鍵指標（本週／上週／變化）、需要決定的事項、外部情報前 3 則、資料品質提醒 | 管理層週報 |
| 進度預警 | 預警清單：燈號、規則、案子、為什麼、建議跟誰確認 | 項目進度看板 |
| 進度明細 | 每案：類別、階段、負責人、下一個日期、距今天數、燈號 | 項目進度看板 |
| 外部情報 | 情報追蹤表（日期、來源、標題、連結、分類、摘要、分數） | 外部情報摘要 |
| 指標歷史 | 每週一列，累積關鍵指標，可以畫趨勢 | 管理層週報（**只新增、不覆蓋**） |
| 說明 | 資料截至日期、執行編號、資料等級、待補清單、計算方法 | 各系統頁尾 |

不會出現在試算表的內容：看板的「卡點／風險」「備註」「近期下一步」（系統本來就不讀或不輸出），以及任何財務資料（財務上線後另開一份權限更嚴的試算表）。

## 3. 怎麼連到 Google
| 項目 | 做法 |
|---|---|
| 帳號 | 在公司 Google Workspace 建一個「服務帳號」（給程式用的帳號），只把「管理層系統」這份試算表分享給它編輯 |
| 金鑰 | 服務帳號的金鑰檔放在公司電腦，路徑寫在 `.env`（不提交）；程式碼與設定檔不出現任何金鑰 |
| 試算表位置 | 試算表 ID 寫在 `config/sheets.yaml`；分頁名稱也在這裡，可改 |
| 誰看得到 | 試算表只分享給執行長與主管（由主管在 Google 上設定） |
| 新套件 | 需要安裝 `gspread`、`google-auth` 兩個 Python 套件（輕量，不是重型工具），**依 CLAUDE.md 第 6 節要先經你同意** |

## 4. 規則
- 寫入前先檢查：試算表 ID、金鑰路徑都有設定、服務帳號有編輯權限；任一項沒有就停止同步並說明，不影響本機報表。
- 寫入內容一律來自本機已產生的報表／摘要檔，不重新計算。
- 「週報」「進度預警」「進度明細」「外部情報」「說明」每次整頁覆蓋；「指標歷史」同一週重跑只更新那一列，不重複新增。
- 每個分頁第 1 列寫資料等級與「資料截至」，和本機報表一致。
- 以「=」開頭的文字以純文字寫入，不變成公式。
- 不刪除或修改主管自己在試算表裡另外新增的分頁。

## 5. 測試與驗收條件
| # | 條件 | 現在能驗證嗎 |
|---|---|---|
| 1 | 用假的 Google 連線（測試替身）驗證每個分頁寫入的內容等於本機報表 | 能 |
| 2 | 同一週重跑，指標歷史不重複；不同週會新增一列 | 能 |
| 3 | 沒設定或權限不足時，本機報表照常產生，並有白話提示 | 能 |
| 4 | 試算表中沒有卡點／風險、備註、近期下一步的內容 | 能 |
| 5 | 測試不連網路；程式碼與倉庫中沒有任何金鑰 | 能 |
| 6 | 實際寫入公司試算表一次，主管能在瀏覽器／手機打開 | **無法驗證**，要等公司建好服務帳號與試算表 |
| 7 | ruff、pytest 全過；獨立驗收 | 能 |

## 6. 需要你確認的事
1. **公司用的是 Google Workspace 嗎？**（問題清單第 1 題）不是的話這個做法不適用，要改成 OneDrive／SharePoint 的版本。
2. **同意安裝 `gspread`、`google-auth` 兩個套件嗎？**
3. **誰可以在公司 Google 建立服務帳號與試算表？** 通常需要 Workspace 管理員或主管。我會寫一份逐步設定說明給他。
4. **分頁規劃（第 2 節）可以嗎？** 特別是：試算表要不要放案名與負責人（等級「內部一般」，與目前的週報相同）。
5. **第一版只做單向同步可以嗎？** 外部情報的「已讀」標記仍在本機 Excel 填；如果主管想直接在試算表勾已讀，第二版再做讀回。

## 6.1 獨立驗收後追加的規則
- 同步時自動讀專案資料夾的 `.env`（不另裝套件），已存在的環境變數優先；金鑰路徑可用 `~`、可加引號。
- 週報資料檔缺欄位、型別錯、編碼錯，報表 xlsx 壞檔或缺必要欄位，一律白話提示並停止，不崩潰。
- 週報記錄的系統狀態不是「本週已更新」時，對應分頁寫「本週未更新」，不寫舊資料。
- 寫入真實試算表時不先清空，一次覆蓋（失敗時舊內容還在）；寫到一半失敗會列出哪些分頁已更新、哪些沒有。
- 同名但不是系統寫的分頁（第 1 列不是「資料等級：」／「週報日期」）會停下來，不覆蓋。
- 指標歷史保留主管自己的欄、註記列、表頭外的格子與公式；數字以數字寫入；日期不同寫法視為同一週；看不懂的格式不改動並提醒。
- 分頁名稱檢查（1–100 字、不含 [ ] / \ ? * : ..、不重複）；預覽 CSV 只寫在預覽資料夾內，以 = + - @ 開頭的值加前置單引號。
- 一鍵執行的結果訊息會說明「本週沒有同步」的原因（未設定、已停用或週報沒產生）。

## 7. 不做
- 不做網站、不接 Vercel、不設排程（仍由 `run_weekly.py` 手動執行）。
- 不同步財務資料、不同步原始看板。
- 不從試算表讀回任何資料（第一版）。
- 不對外分享試算表；分享設定由主管在 Google 上管理。
