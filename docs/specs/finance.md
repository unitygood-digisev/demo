# 規格：項目財務總覽（系統 2，src/finance）

前置條件：執行長已明確核准可提供的資料範圍。未核准前不要建置真實資料的載入，只用假資料開發與測試。
資料等級：內部敏感。這個系統不需要大模型，全部用 Python 計算，禁止呼叫 llm_client。

## 目標
管理層一頁看懂：項目賺不賺錢、哪些款項還沒收到、哪些項目的成本和進度不匹配。

## 輸入（data/raw/，由會計系統匯出的 Excel）
- contracts.xlsx：project_id、客戶、合約總價、幣別、付款期數與比例。
- settlement.xlsx（會計「專案結算」匯出）：project_id、已認列收入、已發生成本、外包成本。
- receivables.xlsx：invoice_id、project_id、發票日、到期日、金額、已收金額、收款日。
- 實際匯出格式不確定。先要求我提供去識別的樣本（前 10 列），再寫 config/finance_columns.yaml 的欄位對應。
- 幣別如果不是 TWD，標「幣別待確認」，不要自己換算。

## 計算公式（輸出頁尾附「計算方法」）
- 毛利率 = (已認列收入 − 已發生成本) ÷ 已認列收入。分母為 0 時顯示「待補」。
- 未收金額 = 金額 − 已收金額。
- 帳齡分組按「今天 − 到期日」的天數：未到期、0–30、31–60、61–90、超過 90 天。
- 已請款比例 = 累計發票金額 ÷ 合約總價。
- 成本佔合約比 = 已發生成本 ÷ 合約總價。
- 金額四捨五入到元。所有公式如果與會計系統的數字不一致，以會計系統為準，並在輸出列出差異。

## 預警規則（thresholds.yaml，起始值待主管確認）
- F01 帳齡超過 90 天的未收款 → 紅。
- F02 毛利率低於門檻 → 黃。
- F03 成本佔合約比超過 X%，但里程碑完成率低於 Y%（需要系統 1 的資料） → 紅。
- F04 已請款金額超過合約總價、已收金額超過發票金額、負值金額 → 資料錯誤，列入「資料品質」。

## 輸出
- xlsx：總覽（總未收、逾期金額、帳齡分布、三句結論）、項目財務表、應收明細、預警、資料品質、計算方法。
- 檔案頁首標「內部敏感：僅執行長與主管」，存到環境變數 FINANCE_OUT_DIR 指定的公司資料夾，不寫到專案倉庫。

## 驗收條件
- 帳齡各組金額加總 = 未收金額總和（寫成測試）。
- 每個項目的每個數字都能追到輸入檔的列。
- 分母為 0、負值、幣別不一致、重複發票都有測試，這些情況顯示「待補」或資料錯誤，不填 0。
- 程式碼裡不得 import llm_client（寫成測試）。

## 不做
- 不自己推斷收入認列規則，不重算會計系統已有的數字，不發送任何內容。
