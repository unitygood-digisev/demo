# 規格：項目進度與預警看板（系統 1，src/progress）

目標：管理層一頁看懂哪些項目有逾期風險、哪些負責人同時負荷偏高，以及跟上週相比有什麼變化。
資料等級：內部一般（不讀合約條款和金額）。

## 輸入（data/raw/，Excel）
- projects.xlsx：項目清單。必填欄位：project_id、客戶、專案名稱、負責人、起始日、預計結案日、狀態（未開始／進行中／已結案／暫停）。
- milestones.xlsx：里程碑。必填欄位：project_id、里程碑名稱、預計日、實際完成日（可空）、狀態。
- updates.xlsx：更新紀錄。必填欄位：project_id、更新日、備註。
- 欄位名稱與實際檔案不同時，用 config/progress_columns.yaml 做對應，不要改使用者的檔案。
- 這三個檔案還不存在時，先在 data/sample/ 產生假資料，並在 docs/data_requests.md 列出要求主管提供的真實檔案格式。

## 預警規則（config/thresholds.yaml，每個值都標「待主管確認」）
- A01 里程碑逾期：預計日已過且狀態不是「已完成」→ 紅。
- A02 里程碑即將到期：N 天內到期（起始值 7）且狀態是「未開始」→ 黃。
- A03 長期無更新：進行中項目超過 N 天（起始值 14）沒有更新紀錄 → 黃。
- A04 負荷偏高：同一位負責人同時進行的項目超過 N 個（起始值 5）→ 黃。只顯示「負責人＋項目數」，按姓名排序，不做排名、不評價。
- A05 結案逾期：預計結案日已過且狀態不是「已結案」→ 紅。
- A06 資料品質：缺必填欄位、日期格式錯、重複 project_id → 列入「資料品質」分頁，不計入預警。

## 處理步驟
1. 讀入並驗證（用 shared/io.py），錯誤整張列出。
2. 計算預警：今天的日期要可以由參數注入（方便測試），預設用台灣時區的今天。
3. 與上週快照（data/interim/progress_snapshot_YYYYMMDD.csv）比較，產生「新增預警／已解除／持續」。
4. 輸出：
   - xlsx：總覽（紅黃綠數量、三句結論）、預警清單（項目、規則、為什麼、建議跟誰確認）、項目明細（條件式色彩）、資料品質。
   - 1 頁 .md 摘要。

## 驗收條件
- 每條規則都有測試，包含邊界日（剛好 N 天、剛好過期當天）。
- 使用假資料重跑兩次，結果相同。
- 缺欄位、重複 ID、日期錯誤都出現在「資料品質」，不會讓程式崩潰也不會被靜默跳過。
- 「總覽」的數字與預警清單的筆數一致（寫成測試）。
- 任何人可以只改 thresholds.yaml 就改變門檻，不需要改程式。

## 不做
- 不讀合約金額，不做個人排名，不自動發通知給顧問。
