# 規格：項目進度與預警看板（系統 1，src/progress）

> 2026-10-14 修訂：原規格假設三個檔案（項目清單、里程碑、更新紀錄），但公司實際只有一份「項目進度看板」Excel。依階段 2 計畫（docs/decisions/phase2.md）改為直接讀現有看板，規則改為 P01–P05，拿掉原 A05（看板沒有預計結案日）。

目標：管理層一頁看懂哪些案子需要注意、跟上週相比有什麼變化，以及看板本身哪裡缺資料。
資料等級：內部一般。看板的「卡點／風險」「備註」含客戶未公開資訊，**系統不讀入、不輸出**；「近期下一步」只用來判斷 P04 有沒有變化，紀錄中只存雜湊，**不輸出原文**。所以輸出維持內部一般。

## 輸入（data/raw/，公司現有看板）
- 檔名符合 `項目進度看板*.xlsx`，取檔名排序最後一個；也可用 `--input` 指定。
- 讀「項目看板」分頁。標題列用「客戶／案子」自動找，上方說明文字自動跳過。
- 讀入欄位：客戶／案子（必填，當作案子識別）、類別、階段（必填，須在下拉選單內）、負責人、近期下一步、下一個日期。
- 欄名或分頁名稱改變時，改 config/progress_columns.yaml，不改程式、不改使用者的檔案。
- 看板資料日期：從標題列上方說明文字中的 `YYYY/M/D` 取得。
- 不讀「待辦事項」「後續追蹤項」「角色切入點」等其他分頁。

## 預警規則（門檻在 config/thresholds.yaml，都標「待主管確認」）
- P01 下一步日期已過：下一個日期早於今天，且階段不是「已完成」→ 紅。
- P02 下一步即將到期：下一個日期在今天起 N 天內（含今天，起始值 7），且階段不是「已完成」→ 黃。
- P03 卡關：階段是「卡關」→ 紅。
- P04 長期沒有變化：進行中／結案中／卡關的案子，連續 N 天（起始值 14）「階段、近期下一步、下一個日期」都沒變（依歷次快照）→ 黃。快照紀錄不足 N 天時在待補清單註明可能漏報。
- P05 負責案數偏多：同一負責人負責的進行中／結案中／卡關案子超過 N 個（起始值 5）→ 黃。只算括號外的人名（「、」「／」分開的都算），「行政」「全體專案人員」等非人名不算。只顯示「負責人＋案數」，按姓名排序，不排名、不評價，註明「排程參考，不是績效評估」。
- 每案燈號＝該案所有預警中最嚴重者；沒有預警為綠。
- 資料品質（不計入預警）：缺案名、案名重複、日期錯誤、階段不在選單內、進行中／結案中／卡關的案子缺下一個日期或負責人、標題列或分頁找不到。
- 看板資料日期距今超過 N 天（起始值 7）時，在結論提醒「看板可能沒有更新」。

## 處理步驟
1. 讀入並驗證（shared/io.py），錯誤整張列出。
2. 計算預警；「今天」可由參數指定，預設台灣時區的今天。
3. 與上次執行比較（data/interim/progress/runs/），產生「新增／解除／持續」，以及看板新增、消失的案子。
4. 存本次快照（data/interim/progress/snapshots/：案子、階段、近期下一步的雜湊、下一個日期；不含卡點／風險、備註）供下次比較。指定日期早於已處理的最新日期時拒絕執行。
5. 輸出（data/out/progress/）：
   - `進度看板_YYYYMMDD.xlsx`：總覽（三句結論、紅黃綠數量、各規則筆數）、預警清單、項目明細（燈號上色）、本週變化、負責人案數、資料品質。
   - `進度摘要_YYYYMMDD.md`：一頁摘要。
   - `summary.json`：給管理層週報。

## 驗收條件
- 每條規則都有測試，包含邊界日（今天到期、剛好 N 天、過期 1 天、剛好 N 案和 N+1 案）。
- 使用假資料重跑兩次，結果完全相同。
- 缺欄位、案名重複、日期錯誤都出現在「資料品質」，不會讓程式崩潰也不會被靜默跳過。
- 「總覽」的數字與預警清單的筆數一致（寫成測試）。
- 只改 thresholds.yaml 就能改門檻。
- 輸出與中間紀錄都不含「卡點／風險」「備註」「近期下一步」的內容（寫成測試）。

## 不做
- 不讀合約金額，不做個人排名，不自動發通知給顧問，不修改原始看板，不猜缺少的日期。

## 附：會議紀錄補齊建議（階段 2b，2026-10-15 新增）
- 輸入：`data/raw/meetings/` 的會議紀錄（UTF-8 文字檔，檔名含 8 碼日期）、最新看板、本機案名對應表 `config/meeting_aliases.yaml`（不提交）。規則在 `config/meetings.yaml`，門檻 `meetings.max_age_days` 在 `config/thresholds.yaml`。
- 輸出：`data/out/progress/看板補齊建議_YYYYMMDD.xlsx`，分頁：建議補上的日期、與看板不一致、看板沒有的案子、待人工確認、會議紀錄清單。資料等級「內部一般」。
- 規則：
  - 看板較新時以看板為準，不改看板，只提出建議。
  - 比看板早超過 `max_age_days` 天的紀錄只存檔、不比對。
  - 年份＝會議那一年；該行寫「明年」時加一年。「9 月底」等寫法列為約略時程，不換算成某一天。
  - 只採用看板資料日期當天或之後的日期。
  - 對到多案、看板同名、對不到案子的日期，列入待人工確認，不猜。
  - 財務、人事、行政段落不讀；輸出只含案名、日期、階段字眼與出處（檔名＋行號），不含紀錄原文。
- 計畫與決定：docs/decisions/phase2b_meetings.md。
