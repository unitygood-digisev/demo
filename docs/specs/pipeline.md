# 規格：業務漏斗與商機看板（系統 4，src/pipeline）

目標：管理層看懂商機卡在哪一步、展會和永續評鑑帶來多少名單、哪些來源真的有成交。
資料等級：客戶機密（含個資）。不使用大模型，禁止呼叫 llm_client。

## 輸入
- leads.xlsx：lead_id、來源（展會／永續評鑑／介紹／其他）、登記日、公司、目前階段、階段日期紀錄。聯絡人姓名和電話有時在同一檔，讀入後丟棄，輸出只列公司名稱。
- proposals.xlsx：proposal_id、lead_id、提案日、報價日、報價金額、結果（成交／未成交／進行中）、結果日、原因。
- assessment_results.xlsx（永續評鑑匯出）：公司、日期、等級或分數。實際格式未知，先要樣本再寫欄位對應。
- config/pipeline_stages.yaml：階段定義。起始版（待主管確認）：留名單→初次接觸→需求確認→提案→報價→成交／未成交。
- config/loss_reasons.yaml：未成交原因分類清單，原因欄用關鍵字規則歸類，歸不進去的放「其他／待補」，不用大模型。

## 計算
- 各階段筆數（以「曾到達的最高階段」計）與報價金額。
- 階段轉換率 = 進入下一階段的筆數 ÷ 進入本階段的筆數。
- 平均停留天數。
- 卡關名單：在同一階段超過 N 天（起始值 21，待確認）。
- 來源成效：每個來源的名單數、成交數、成交金額。
- 加權管道金額：只在 config 有明確的各階段機率時才算，沒有就不顯示，不要自己訂機率。

## 輸出
- xlsx：總覽（三句結論、漏斗圖）、卡關名單（公司、階段、天數）、來源成效、未成交原因分布、資料品質。
- 檔案頁首標「客戶機密：僅執行長與主管」。

## 驗收條件
- 輸出檔不含任何聯絡人姓名、電話、電子郵件（掃描測試）。
- 階段筆數和轉換率用手算的小型假資料驗證一致。
- 缺階段、重複 lead_id、日期錯誤列入資料品質。
