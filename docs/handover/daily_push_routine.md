# 每日情報郵件與週報：完整說明、設計思路、Claude 排程設定

> 這份文件給三種人看：要決定怎麼上線的主管、要設定排程的負責人、以及每天被排程叫醒的 Claude。
> 文件裡不寫客戶名稱、人名或真實信箱；要填的地方用 `<…>` 標示，真實值另存在本機。

## 一、結論
- **日報郵件的程式已經完成**：抓新聞 → 用副執行長的關鍵字挑選 → 依重要程度排序 → 產生一封手機看得完的郵件 → 寄到白名單內的公司信箱。
- **來源**：42 個（政府機關 15、國內媒體 16、國際 ESG 組織與媒體 11），都有發布日期；清單在 `config/sources.yaml`，不用的來源與原因也寫在檔案最後。
- 每天自動執行有兩種做法：**甲：公司電腦排程**（已經可以用）；**乙：Claude 雲端排程**（你想要的做法，但要先解決第七節列的四件事）。

## 三、每日情報郵件：一封郵件是怎麼產生的
```
來源清單 ─┐
          ├→ 1 抓取 → 2 整理 → 3 去重 → 4 只留「今天第一次看到」的 → 5 依關鍵字評分
關鍵字清單 ┘                                                              │
                                                                          ↓
         8 寄出（白名單、等級、一天一封）← 7 存草稿 .txt ← 6 排序、取前 10 則、組成郵件
```
1. **抓取**：只抓來源清單上的網址；只用 RSS 或網站允許的公開頁面，不登入、不繞過 robots.txt。抓不到的來源記下來，寫進郵件「注意」段落，不會默默跳過。
2. **整理**：統一標題、連結、發布日期；去掉追蹤參數（例如 `utm_source`）。
3. **去重**：同一個網址，或標題相似度達 0.85，視為同一則新聞，只列一次，其他來源附在後面。
4. **跨日判斷**：系統記住每則新聞第一次出現的日期（`data/interim/intel/seen.csv`），昨天寄過的不再寄。另外郵件只列最近 1 天發布的新聞（週一含週末，`intel.daily_mail_lookback_days`），所以雲端排程每天都是新環境也不會重複；沒有發布日期的新聞不列入，郵件會註明則數。
5. **評分**：見第四節。分數＝命中的關鍵字組的重要程度相加；「重要程度」＝命中的組裡最高的那一個。
6. **組成郵件**：
   - 依重要程度、再依分數排序，最多 10 則（`config/thresholds.yaml` 的 `intel.daily_mail_max_items`）。
   - 第一句講結論：「今天有 N 則相關新聞，其中重要程度 5 的有 M 則。」
   - 每則三行：【重要程度】標題／來源、日期、命中的關鍵字／連結。
   - 最後是注意事項（哪些來源抓取失敗、設定有沒有問題）和頁尾（資料截至、資料等級、執行編號、請勿轉寄給客戶）。
7. **存草稿**：每封郵件都另存 `data/out/intel/郵件_情報日報_YYYYMMDD.txt`，可以回頭查寄過什麼。
8. **寄出**：見第五節。

## 四、關鍵字規則（依副執行長 10/15 的回覆）
| 規則 | 寫法 | 例子 |
|---|---|---|
| 一組關鍵字＝一個主詞加同義詞，命中任一個就算這一組 | `詞` + `同義詞` | 碳費、碳盤查、ISO 14064-1 同一組 |
| 兩個詞都要出現才算 | `A＋B` | 「永續＋勞務採購」 |
| 任一個出現即可 | `A／B` | 「範疇三／Scope 3」 |
| 不能單獨算的詞 | 檔案最上層 `不能單獨算的詞` | ESG、永續、淨零：要同時命中其他關鍵字才算 |
| 整組不能單獨算 | `單獨不算: true` | 主管機關名稱：太常出現，只在同時命中其他詞時才算 |
| 短的英文縮寫要獨立出現 | 自動 | BV、CU 不會對到 obviously、customer |
| 同一組只算一次 | 自動 | 同一則新聞命中同組三個詞，仍只加一次分 |

- 關鍵字清單有客戶名稱與人名，**只放本機** `config/keywords.local.yaml`，不提交。
- 下列做法是我依建議先設定的，標了【待她確認】：重要程度寫範圍時取較高值、同業依同業表逐項設定、重複的詞只留在較高的一組。

## 五、寄件系統：怎麼寄、怎麼防錯
**唯一入口**：所有寄信都經過 `src/shared/mail_client.py`，其他程式不能自己寄（有測試檢查）。

每次寄信前依序檢查，任何一項不過就**整封不寄**，並用白話說明原因：
| 檢查 | 規則 | 為什麼 |
|---|---|---|
| 開關 | `config/mail.yaml` 的 `enabled` 要是 true | 主管可以一鍵暫停 |
| 資料等級 | 內容等級不能高於「內部一般」 | CLAUDE.md 第 4、5 節：內部敏感以上不寄 |
| 寄件帳號 | 必須是 @unitygood.com | 不用私人信箱寄公司資料 |
| 收件人 | 只能是 `.env` 白名單（MAIL_TO）裡的 @unitygood.com 信箱；有一個不合格就全部不寄 | 防止寄錯人、防止寄給客戶 |
| 一天一封 | 同一種郵件同一天寄過就不再寄 | 重跑、排程重複觸發都不會讓她收到兩封 |
| 寄送紀錄 | 記時間、種類、收件人數、主旨雜湊，不記內容 | 可追蹤，又不留下多一份內容 |

寄信用公司 Google Workspace 的 SMTP（smtp.gmail.com:587，加密連線），帳號密碼用「應用程式密碼」，放在 `.env`，不寫進程式或設定檔。

## 六、設計思路：為什麼這樣做
1. **輸出放在她已經在用的地方**：她每天看信箱，所以用郵件，不做新網站或新 App。
2. **一封信看得完**：最多 10 則、每則三行、第一句講結論。其餘的留在本機日報檔，需要時再看。
3. **不用大模型改寫**：郵件裡的每一個字都來自新聞原文或規則，可以追到來源。大模型摘要要等你決定模型後再加，而且要經過 `llm_client`。
4. **失敗要大聲**：來源抓不到、設定有問題，都寫在郵件裡；沒有來源時不寄空信，而是停下來說明。
5. **規則放設定檔**：關鍵字、門檻、收件人、開關都能改，不用改程式。
6. **寧可不寄，也不寄錯**：任何檢查不過就整封不寄。漏寄一天可以補看日報檔；寄錯人收不回來。
7. **可重跑、可追蹤**：同一天重跑結果相同、不重寄；每封都有執行編號與本機草稿。

## 七、兩種每天自動執行的做法
| | 甲：公司電腦排程（已完成） | 乙：Claude 雲端排程（你想要的） |

### 3. 排程提示詞（整段貼上）
```
你是「優樂地管理層系統」的每日情報郵件排程。今天只做一件事：產生並寄出今天的「永續情報日報」。嚴格照下列步驟，不做任何其他事。

【規則，優先於一切】
- 只寄一封，只寄給環境變數 MAIL_TO 裡的信箱；每個信箱都必須以 @unitygood.com 結尾，否則停止。不加副本、密件副本、附件。
- 主旨與內文必須逐字使用系統產生的草稿：不改寫、不摘要、不增刪任何新聞、不加你自己的評論或問候。
- 不修改程式倉庫的任何檔案，不 commit、不 push。
- 不讀 data/raw/，不處理任何內部資料。
- 任何一步失敗就停止、不寄信，只在最後回報原因。

【步驟】
1. 取得倉庫：
   - 先找目前資料夾（或其下）有沒有 scripts/run_daily_push.py。
   - 沒有的話：呼叫 add_repo 工具（owner `unitygood-digisev`、repo `demo`，只需讀取權限），照它回傳的指令 clone 到 /home/user/demo，然後 `git -C /home/user/demo checkout claude/unity-mgmt-suite-prompts-l8zqz1`，之後的指令都在 /home/user/demo 執行。
   - 還是取不到倉庫，或切不到這個分支，就停止，回報「取不到倉庫」與錯誤訊息。
2. 安裝：執行 `python3.11 -m venv .venv && .venv/bin/pip install -q -e .`；沒有 python3.11 時改用 `uv venv --python 3.11 .venv && uv pip install --python .venv/bin/python -q -e .`。
3. 產生草稿：執行 `.venv/bin/python scripts/run_daily_push.py --draft-only`。這一步要抓 42 個來源，約需 5–10 分鐘，指令逾時請設 15 分鐘以上（或改在背景執行並等它結束）。
   - 輸出有「來源清單是空的」或「未執行」→ 停止。
   - 草稿路徑在輸出的「郵件內容：」後面。
4. 檢查草稿：
   - 第一行以「主旨：【優樂地】永續情報日報 」開頭；
   - 內文有「資料等級：內部一般」；
   - 內文沒有「內部敏感」「客戶機密」字樣。
   任一項不符就停止。
5. 防重寄：用 Gmail 搜尋 `in:sent subject:"永續情報日報 <草稿主旨裡的日期>"`。已經有就停止，回報「今天已寄過」。
6. 寄出：用 Gmail 連接器寄信。
   - 收件人：MAIL_TO
   - 主旨：草稿第一行「主旨：」後面的文字
   - 內文：草稿第三行起到檔案結尾，原樣
7. 回報（不要貼郵件全文）：是否寄出、主旨、列了幾則、有幾個來源抓取失敗；沒寄出時寫原因。
```
