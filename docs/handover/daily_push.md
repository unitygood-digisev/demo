# 移交手冊：每日永續情報郵件

## 這是什麼
每天早上，系統到指定的新聞來源抓新聞，用副執行長提供的關鍵字挑出相關的，依主題分組（每個主題最多 3 則，依重要程度排序），寄到她的公司信箱。

- 郵件只有新聞的**標題、來源、日期、命中的關鍵字、連結**。
- 只會寄給 `.env` 白名單裡的 **@unitygood.com 公司信箱**，寄給其他信箱會被系統擋下。
- 同一天重跑不會重寄。
- 每封郵件另存一份文字檔：`data/out/intel/郵件_情報日報_日期.txt`。

## 第一次設定（約 20 分鐘）
### 1. 建立寄件帳號的「應用程式密碼」
寄件帳號是公司信箱（目前用數位轉型實習生的帳號）。
1. 用寄件帳號登入 Google，打開「管理你的 Google 帳戶」→「安全性」。
2. 開啟「兩步驟驗證」（已開過就跳過）。
3. 在「安全性」搜尋「應用程式密碼」，新增一個，名稱填「管理層系統」。
4. 複製畫面上的 16 碼密碼（只會顯示一次）。

找不到「應用程式密碼」，通常是公司 Google Workspace 管理員關掉了這個功能，請管理員開啟。

### 2. 填 `.env`
在專案資料夾的 `.env` 加入三行（`.env` 不會上傳）：
```
MAIL_FROM=寄件帳號@unitygood.com
MAIL_APP_PASSWORD=剛剛的16碼密碼
MAIL_TO=收件人@unitygood.com
```
收件人有好幾位時，用逗號分隔。只能填公司信箱。

### 3. 設定新聞來源和關鍵字
- 關鍵字：`config/keywords.local.yaml`（已依副執行長 10/15 的回覆建好，只放在公司電腦）。
- 來源：`config/sources.yaml`。**來源還沒設定之前，系統只產生草稿，不會寄信。**

### 4. 試寄一次
```
.venv/bin/python scripts/run_daily_push.py
```
看到「已寄出」，就到她的信箱確認。

## 每天自動寄（排程）
系統要放在一台**每天開機**的公司電腦上。

**Windows：工作排程器**
1. 開始功能表搜尋「工作排程器」→「建立基本工作」。
2. 名稱填「永續情報日報」。觸發程序選「每週」，勾選週一到週五，時間 08:00。
3. 動作選「啟動程式」：
   - 程式：專案資料夾裡的 `.venv\Scripts\python.exe`
   - 引數：`scripts\run_daily_push.py`
   - 開始位置：專案資料夾的完整路徑
4. 完成後，在工作上按右鍵「執行」試一次。

**Mac／Linux：cron**
執行 `crontab -e`，加入一行（路徑換成專案資料夾）：
```
0 8 * * 1-5 cd /路徑/unity-mgmt-suite && .venv/bin/python scripts/run_daily_push.py >> logs/daily_push.log 2>&1
```

## 郵件長什麼樣子
```
主旨：【優樂地】永續情報日報 2026-10-15（5 則）

今天有 5 則相關新聞，其中重要程度 5 的有 2 則。

1. 【重要程度 5】新聞標題
   來源：某新聞稿｜日期：2026-10-14｜關鍵字：碳費
   連結：https://...
...
注意：有 1 個來源今天抓取失敗：某來源
---
資料截至：2026-10-15｜資料等級：內部一般｜執行編號：…
```
想先看看：`.venv/bin/python scripts/run_daily_push.py --sample`（假資料，不寄信）。

## 常見訊息
| 看到什麼 | 怎麼處理 |
|---|---|
| 「未寄出：來源清單是空的」 | 還沒設定 `config/sources.yaml` |
| 「未寄出：尚未設定寄件帳號、應用程式密碼或收件人」 | 做「第一次設定」的第 2 步 |
| 「寄件帳號登入失敗」 | 應用程式密碼錯了或被刪了，重新建立一個 |
| 「收件人…不是公司信箱，已全部拒寄」 | `.env` 的 MAIL_TO 只能填 @unitygood.com |
| 「今天已經寄過，沒有重寄」 | 正常。一天只寄一封。注意：刪掉 `data/interim/mail/sent.jsonl`（寄送紀錄）會讓系統以為今天還沒寄 |
| 「寄送紀錄…壞掉／無法讀取，為避免重寄已停止」 | 請負責人打開 `data/interim/mail/sent.jsonl`，刪掉壞掉的那一行後再跑 |
| 「未寄出：只能寄今天的日報」 | 指定了 `--as-of` 其他日期時只產生草稿，不寄 |
| 「寄信失敗（…）」 | 多半是網路暫時不通，稍後再跑一次 |
| 郵件寫「有 N 個來源今天抓取失敗」 | 那個網站暫時連不上，或網址改了；連續幾天都失敗就請負責人檢查 |

## 要調整的時候
- 加減關鍵字、改重要程度：編輯 `config/keywords.local.yaml`。寫法說明在檔案開頭：「A＋B」表示兩個詞都要出現，「A／B」表示任一個即可（都用全形符號；半形 + 當一般文字）。
- 每個主題最多幾則：`config/thresholds.yaml` 的 `intel.daily_mail_per_topic`；總則數上限 `intel.daily_mail_max_items`（空白＝不設上限）。
- 新聞歸到哪個主題：關鍵字檔每一組的「主題」。
- 加收件人：在 `.env` 的 MAIL_TO 加上公司信箱。
- 暫停寄送：把 `config/mail.yaml` 的 `enabled` 改成 `false`，或在排程裡停用這個工作。

## 誰負責
- 設定與排程：數位轉型實習生（之後交接給指定的內部窗口）。
- 關鍵字清單：副執行長。
- 新聞來源清單：副執行長確認，負責人維護。
