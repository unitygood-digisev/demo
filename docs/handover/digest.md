# 移交手冊：管理層週報

## 這是什麼
每週一頁的管理層週報。它**不讀任何原始資料**，只把各系統跑完後留下的摘要（summary.json）排成一頁：

1. **本週結論**：各系統一句結論，加一句狀態說明（哪個系統沒更新、資料品質問題有幾項）。
2. **關鍵指標**：本週／上週／變化。
3. **需要您決定的事項**：各系統的紅色預警，最多 5 條。
4. **外部情報**：最相關的 3 則，標題加連結。
5. **資料品質提醒**：最多 5 條，其餘請看各系統報表。

不使用 AI 改寫，不會自動寄出。

## 每週怎麼跑
最簡單：每週一鍵執行（建議在專案組會議、看板更新之後）：
```
.venv/bin/python scripts/run_weekly.py
```
它會依序跑「外部情報摘要（含每週彙整）→ 項目進度看板 → 管理層週報」。某一步失敗時，其他照跑，最後會列出哪些步驟沒完成；週報會把失敗的系統標成「本週執行失敗，未納入」，**不會拿上週的舊數字充當本週**。要指定日期：`--as-of 2026-10-19`。

只想重新產生週報（其他系統已經跑過）：
```
.venv/bin/python scripts/run_digest.py
```

先用假資料看看長什麼樣子：`.venv/bin/python scripts/run_digest.py --sample`（輸出在 `data/out/digest_sample/`）。

## 會產生哪些檔案（在 `data/out/digest/`）
| 檔案 | 用途 |
|---|---|
| `管理層週報_日期.docx` | 一頁 Word，可列印或附檔 |
| `管理層週報_日期.md` | 同內容，方便預覽 |
| `管理層週報_郵件版_日期.txt` | 純文字，整段複製貼到郵件內文即可 |

頁首會標資料等級，取所有來源中最高的等級（目前是「內部一般」）。財務上線後可能變成「內部敏感：僅執行長與主管」，轉發時請注意收件人。

## 怎麼看
- **「本週未更新」**：那個系統的摘要超過 7 天沒更新，或找不到摘要檔。請先跑那個系統，再重新產生週報。
- **「摘要檔格式錯誤，未納入」**：那個系統的摘要檔壞了（例如數字欄位不是數字）。重跑該系統通常就會好；還是不行就聯絡負責人。
- **「本週執行失敗，未納入」**：一鍵執行時那個系統沒跑成功，週報不使用它的舊資料。
- **「系統尚未上線」**：例如財務總覽，等核准並建置完成後才會出現數字。
- **「待補」**：上週沒有數字可以比（例如第一次執行）。
- **頁尾「待補清單」**：列出這份週報的限制，例如外部情報仍是模擬摘要、指標清單還沒經主管確認。

## 可以調整的設定
| 想改什麼 | 改哪裡 |
|---|---|
| 週報要看哪些指標、順序 | `config/metrics.yaml`（主管確認後，把 `status` 改成「已確認」） |
| 幾天沒更新算「本週未更新」 | `config/thresholds.yaml` 的 `digest.stale_days`（目前 7） |
| 決定事項、情報、資料品質各列幾條 | `config/digest.yaml` |
| 財務系統上線 | `config/digest.yaml` 把 finance 的 `launched` 改成 `true`，並設定環境變數 FINANCE_OUT_DIR |

## 常見狀況
| 看到什麼 | 怎麼處理 |
|---|---|
| 某系統一直「本週未更新」 | 確認那個系統有跑；用 `run_weekly.py` 就會一起跑 |
| 週報超過一頁 | 系統會自動截短（每段文字最多 160 字、換行壓成一行）；若仍太長，頁尾會寫「仍超過上限」，請調低 `config/digest.yaml` 裡的條數 |
| 「未執行：config/digest.yaml 的…」 | 設定檔寫錯（例如 launched 寫成 "false" 字串），照訊息改正 |
| 想寄給更多人 | 先看頁首的資料等級；「內部敏感」「客戶機密」只給執行長與主管 |

## 誰負責
| 工作 | 負責人 |
|---|---|
| 每週執行、轉發週報 | 待主管指定 |
| 決定週報指標 | 主管（問題清單第 4 題） |
| 系統出問題時聯絡 | 數位轉型實習生（實習結束後：待主管指定） |
