# 移交手冊：用會議紀錄補齊項目看板

## 這是什麼
每月開完業務會議，把會議紀錄交給系統，它會告訴你看板上**還缺什麼**：
- 看板沒填「下一個日期」，但會議裡有講日期的案子 → **建議補上的日期**；
- 看板的日期或階段和會議講的不一樣 → **與看板不一致**（只提醒，以看板為準）；
- 會議有提到、看板上沒有的名稱 → **看板沒有的案子**（可能已結束，也可能漏列）；
- 系統不確定是哪一案的 → **待人工確認**。

系統**不會改看板**，也不會改會議紀錄。看完建議後，請你或負責人自己更新看板 Excel。

報表裡**只有案名、日期和出處**（哪一份紀錄的第幾行），**不會出現會議原文**。財務、人事、行政的段落系統完全不讀。

## 每月怎麼跑
1. 把會議紀錄存成文字檔，放進 `data/raw/meetings/`：
   - 在 Word 選「另存新檔」→ 格式選「純文字（.txt）」→ 編碼選 **UTF-8**。
   - 檔名要有日期，例如 `業務會議紀錄_20261012.txt`。
2. 確認 `data/raw/` 裡的看板是最新的。
3. 在專案資料夾打開終端機，輸入：
   ```
   .venv/bin/python scripts/run_meeting_backfill.py
   ```
4. 打開 `data/out/progress/看板補齊建議_日期.xlsx`。

想先看看長什麼樣子：`.venv/bin/python scripts/run_meeting_backfill.py --sample`（假資料）。

## 報表怎麼看
- **總覽**：第一句是結論，例如「會議紀錄可以幫看板補上 4 案的日期」。
- **建議補上的日期**：「建議日期」是最新一份會議紀錄裡最早的明確日期；只講「10 月底」的，建議日期寫「待補」，約略時程放在旁邊。
- **出處**：打開那份文字檔，找到那一行，就能看到原文。
- **會議紀錄清單**：每份紀錄有沒有用到。太舊的（預設比看板早 45 天以上）只存檔、不比對。

## 讓系統認得簡稱：案名對應表
會議裡常寫簡稱（例如看板寫全名、會議寫兩個字），系統可能對不到。這時：
1. 複製 `config/meeting_aliases.example.yaml`，改名為 `config/meeting_aliases.yaml`。這個檔有客戶名稱，**只放在公司電腦，不會上傳**。
2. 在 `aliases:` 底下一行寫一個：`會議裡的寫法: 看板上的完整案名`。
3. 不是案子的名稱（例如「現場小卡」），寫在 `ignore:` 底下，之後就不會再出現。
4. 再跑一次。

## 常見訊息
| 看到什麼 | 怎麼處理 |
|---|---|
| 「沒有會議紀錄」 | `data/raw/meetings/` 是空的，把紀錄放進去 |
| 紀錄清單寫「檔名沒有日期」 | 把檔名改成含 8 碼日期，例如 `_20261012` |
| 紀錄清單寫「不是 UTF-8 編碼」 | 用記事本打開，另存新檔時編碼選 UTF-8 |
| 「內文的會議日期和檔名不符」 | 確認檔名日期是否正確；系統以檔名為準 |
| 「對應表的…對到看板上沒有的案名」 | 對應表右邊的案名要和看板一字不差 |
| 「同一行對到多個案子」 | 在對應表加一行，指定這個寫法是哪一案 |
| 「看板上有同名的案子」 | 先把看板上重複的案名改成不同 |
| 「這一行有財務、人事或行政字眼，系統未讀取」 | 系統為了不讀到財務內容，整行跳過；請打開紀錄看那一行，需要的話自己更新看板 |
| 「年份不確定（可能是跨年）」 | 例如 12 月的會議寫「1/20」，系統不猜是哪一年；請在紀錄裡寫成「明年 1/20」或「2027/1/20」 |
| 紀錄清單寫「空白檔案」或「檔名日期晚於執行日」 | 檢查檔案內容或檔名日期 |

## 可以調整的設定
- `config/thresholds.yaml` 的 `meetings.max_age_days`：多舊的紀錄只存檔（預設 45 天，待主管確認）。
- `config/meetings.yaml`：哪些段落不讀（財務、人事、行政）、階段字眼、太籠統不拿來比對的字詞。

## 誰負責
- 放會議紀錄、跑系統、維護對應表：數位轉型實習生（之後交接給指定的內部窗口）。
- 確認建議並更新看板：各案負責人。
