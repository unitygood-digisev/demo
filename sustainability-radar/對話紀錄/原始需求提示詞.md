# 原始需求提示詞（使用者 2026-10-17 第一則訊息，全文照錄）

角色與任務
你同時扮演三個角色：資深前端工程師、資料視覺化設計師，以及台灣永續產業（ESG、碳管理）的專家。

請從零做出一個可以實際操作、可以部署上網的網頁系統：《永續情報雷達》。

完成標準：

單一 HTML 檔，加上兩支 Vercel Serverless 函式。
沒有 AI 也能完整使用（離線規則引擎）。
有 AI 時，提供深度解讀、資訊抽取、週報潤飾，以及附引用編號的問答。
所有數字都有可點開的出處與日期，禁止編造任何數字。
完成後，依「測試清單」逐項驗證，再依「部署步驟」部署。

一、產品定義
使用者
台灣的永續顧問與服務公司。服務對象是上市櫃企業與出口製造業客戶；公司的服務線包含碳盤查與查證、永續報告書、IFRS 永續揭露、碳費與自主減量計畫、CBAM 申報、綠電採購，以及永續金融。

主要使用者：公司內的「研究與方案開發團隊」，以及對客戶提案的顧問。

（若要改成企業內部永續長辦公室使用，只要改寫第六節的 CONTEXT 字串與「影響面向」的名稱，其餘架構不變。）

核心痛點
永續法規、國際規範、碳價與客戶要求每週都在變。團隊要花大量時間追新聞、整理數據，還要判斷「這件事會影響哪條服務線、要不要通知哪些客戶」。只做新聞摘要等於 Google News，沒有價值。

系統每週要回答的三個問題
法規與國際規範改變了什麼？ 例如台灣碳費、IFRS S1／S2 接軌、歐盟 CBAM。
碳價與市場往哪裡走？ 我方或客戶的內部碳定價，放在國內外碳價中是什麼位置？碳費和 CBAM 的成本暴險有多大？
同業與客戶在做什麼？ 例如供應鏈減碳要求、RE100、新服務、競爭對手動態。
展示主線（3 分鐘內講完）
訊號（情報）→ 影響（對哪條服務線、哪類客戶）→ 行動（建議做什麼）→ 一鍵產出週報。

讓人記住的互動：「碳價戰情」頁拖動「內部碳定價」滑桿，即時看到它在國內外碳價中的排名，並試算碳費與 CBAM 成本。

AI 的三種執行環境（同一份 index.html 要能在三種環境運作）
Claude Artifact： 用 await window.claude.use('sample') 取得 sample(prompt, opts) 與 sample.json(prompt, opts)。發布時宣告 capabilities: {"sample": {}}。
Vercel 網站： 當 window.claude 不存在且網址是 http(s) 時，先 GET /api/claude。如果回傳 {ok:true}，就建立一個介面完全相同的替身函式 webSample()，改呼叫 POST /api/claude。
離線： 兩者都不可用時 SAMPLE = null。所有 AI 按鈕要隱藏或改成規則版，頁首顯示「離線模式（規則引擎）」。
webSample() 的規格：

call(input, opts) → POST {input, tier: opts.modelTier || 'default'} → 回傳 {text, truncated}；如果有 opts.onText，就呼叫一次並傳入全文。
錯誤時丟出 {code}；HTTP 429 對應 rate_limited，AbortError 對應 cancelled。
call.json 依序嘗試：直接 JSON.parse、解析 Markdown 程式碼框內的內容、擷取第一個 { 或 [ 到最後一個 } 或 ]；全部失敗就丟出 {code:'invalid_json'}。
錯誤處理函式 errText(e)：

not_granted、sampling_disabled：切換成離線模式並重新繪製頁面。
rate_limited：顯示「AI 使用次數暫時達上限，請稍後再試。」
refused：顯示「AI 無法處理這段內容，請換個說法。」
invalid_json：顯示「AI 回覆格式不完整，請再試一次。」
其他：顯示「AI 暫時沒有回應，請再試一次。」
三、設計規格
整體氣氛： 分析師的簡報桌。頂部是報頭（大標題加上雙線底框），下方是分頁列，每個分頁是一個工作面。只有「情報卡」使用卡片樣式。
字型（Google Fonts）： 標題用 Noto Serif TC 700，內文用 Noto Sans TC 400／500／700，數字用 IBM Plex Mono 500／600。每個字型都要有系統字型備援。

版面： 最大寬度 1180px，左右留白 16px；寬度 820px 以下改成單欄。頁面不可以出現水平捲動；表格與圖表放在 overflow-x:auto 的容器裡。
圖表： 全部手寫 SVG，不使用圖表函式庫。

只標關鍵數值，不要每個點都標。
兩個以上的序列要有圖例，禁止雙 Y 軸。
每個資料點都要有滑鼠提示（data-tip 屬性加上一個固定位置的提示框）。
每張圖下方都要寫出處連結，並附「顯示資料表」的表格。
重要度的呈現： 情報卡左邊框用顏色區分（高：--hot、中：--amber、低：--line），並同時寫出文字「重要度 高／中／低」，不能只靠顏色。
文案： 繁體中文、台灣用語、短句、主動語態。按鈕直接寫出會發生的事（例如「加入週報」「複製週報」）。
四、資料原則與查證流程（最重要）
先研究，再寫程式。 用網路搜尋把第五節的每一筆種子資料逐一查證，確認標題、日期、數字與來源網址都正確。查不到或對不上的，就修正或刪除，不可以保留未經證實的數字。
每則情報都必須有： 來源名稱、可點開的原始網址、日期（只知道月份時寫 YYYY-MM，不要猜日期）。
摘要、影響分析、建議行動都要自己改寫，不轉貼原文，避免侵權。
缺值不填補： 某一年的數據找不到，就在圖上標「未取得」並用虛線連接前後兩點，資料表顯示「—」，並註明「公開來源中沒有取得，系統不會自行推估」。
AI 不產生數字： 所有 AI 提示詞都要寫明「只能根據提供的資料，不可編造數字；資料不足時要明說」。
在頁首標示「資料截至 YYYY-MM-DD」，並用常數 AS_OF 管理這個日期。

3. 碳價戰情（取代原本的「利率戰情」）

是否達 2.5 萬噸收費門檻
