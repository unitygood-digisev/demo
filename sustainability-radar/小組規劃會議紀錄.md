# 《永續情報雷達》小組規劃會議紀錄

- 日期：2026-10-17
- 出席：評審（產品與展示把關）、冠軍選手（前端與資料視覺化）、產業專家（台灣 ESG 與碳管理）
- 目標：一頁式、可部署、離線可用的永續情報系統，3 分鐘內講完「訊號 → 影響 → 行動 → 週報」

---

## 議題一：這個系統跟 Google News 差在哪？

**評審**：只做新聞摘要沒有價值。評分時我會看三件事：每則情報有沒有說「影響誰」、有沒有「下一步」、數字能不能點開查。

**產業專家**：顧問公司每週要回答的其實是三個問題：法規改了什麼、碳價往哪走、同業和客戶在做什麼。每則情報都要對應到服務線（碳盤查、碳費、IFRS 揭露、CBAM、綠電、碳權、永續金融），才知道該通知哪個客戶群。

**冠軍選手**：那資料結構就固定成 `lines`（影響面向）＋ `impact`（對我們的影響）＋ `action`（建議行動）。情報卡展開就是這三段，週報的「建議行動」直接從 `action` 組出來。

**結論**
1. 每則情報必填：來源、可點開網址、日期、影響面向、影響分析、建議行動。
2. 情報卡只有一種樣式；重要度用左邊框顏色加上文字「重要度 高／中／低」，不只靠顏色。

## 議題二：讓人記住的互動是什麼？

**冠軍選手**：「碳價戰情」頁的內部碳定價滑桿。拖動時，統計卡、點狀圖上的紅線、解讀文字同時改變。

**產業專家**：解讀要分三段，這是客戶真的會問的：
- 低於台灣碳費一般費率 300 元：內部碳定價沒有反映真實成本。
- 介於台灣與 EU ETS 之間：出口歐盟的產品有 CBAM 價差暴險。
- 高於 EU ETS：對外要能說明訂價依據。

試算要能回答「我要繳多少碳費」「CBAM 大概多少」，並寫清楚 CBAM 可以扣除原產國已付碳價。收費排放量的實際算法以子法為準，畫面上要註明。

**評審**：台灣 50 元和 EU 約 3,000 元差 60 倍，線性座標會把台灣擠成一團。

**冠軍選手**：最高與最低差超過 20 倍時自動改用對數座標，並在軸標題註明。

**結論**：滑桿範圍 0～5,000 元、預設 300；匯率做成可修改的輸入欄，預設值附查詢日期。

## 議題三：數字的可信度

**評審**：編造一個數字就會毀掉整個系統。

**產業專家**：先查證再寫程式。查不到就刪；只知道月份就寫 YYYY-MM。我特別擔心兩件事：
- 二手來源說 2026-09-23 調整 IFRS 接軌範圍，要找到金管會原文。查證結果：已找到金管會與環境部的共同新聞稿，保留（N4）。
- 「CBAM 微量豁免只占總排放不到 1%」容易被誤讀。查證後改寫成「約九成進口商豁免，仍涵蓋逾 99% 的內含排放」（N6）。

**冠軍選手**：缺值不補。圖上標「未取得」、用虛線連前後兩點，資料表顯示「—」。AI 提示詞一律寫「只能根據提供的資料，不可編造數字」。

**結論**：頁首顯示「資料截至」，由常數 `AS_OF` 管理；查證結果另寫成報告。

## 議題四：沒有 AI 也要能用

**冠軍選手**：同一份 `index.html` 有三種環境：
1. Claude Artifact：`window.claude.use('sample')`。
2. Vercel 網站：先 GET `/api/claude`，回 `{ok:true}` 才建立介面相同的 `webSample()`。
3. 離線：`SAMPLE = null`，AI 按鈕全部隱藏，頁首顯示「離線模式（規則引擎）」。

**產業專家**：離線的規則分類器要能判對最常見的句型，例如「環境部預告碳費優惠費率審查新制，明年起上路」要判成法規政策、碳費與自主減量、重要度高。

**評審**：問情報官離線版至少要能用關鍵字找到相關情報，例如問「CBAM 憑證」要找到 N5、N6。

**結論**：規則引擎是正式功能，不是退路；AI 只做深度解讀、資訊抽取、週報主管摘要與附引用的問答。

## 議題五：費用保護

**評審**：公開網站不能讓陌生人燒掉 API 額度。

**冠軍選手**：預設不設 API Key，網站完全免費；`/api/claude` 會回 `{ok:false}`，前端自動進離線模式。要開 AI 時由使用者自己加環境變數，並建議在 Anthropic Console 設每月花費上限。函式時限依 Vercel 免費方案設 60 秒，輸入上限 16,000 字。
