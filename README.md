# 優樂地決策平台

優樂地永續服務股份有限公司：只給執行長與主管用的決策平台。它只回答三件事：這週先處理哪個專案、先催哪筆款、哪個約要續，以及回答問題時能不能引用公司自己的知識。

整套系統都在 Claude 裡執行，不需要其他平台或伺服器：

| 部分 | 在 Claude 裡是什麼 |
|---|---|
| 平台本體（管理層總覽、公司知識庫、筆記、員工） | 一個 Claude Artifact：https://claude.ai/artifact/WRwZtths21n7A2CVemw6RU |
| 資料（專案、請款、知識庫、筆記） | 這個 Artifact 的共用資料庫，只有被分享的人看得到 |
| 三位員工 | 三個 Claude Routine（排程任務），每次執行開一個新的 Claude 對話 |
| 問公司知識顧問 | 平台「員工」頁的問答框，由 Claude 回答 |

## 平台的四個分頁

- **管理層總覽**
  - 匯入 Excel／CSV：先選欄位對映、看前 5 筆預覽，匯入後列出失敗原因。
  - 依固定公式算出四個總數：合約總額、累計已請款、未收款、逾期應收。
  - 列出警示：應收逾期、合約已到期、合約即將到期（90 天內）、請款落後（20 個百分點以上）。
  - 專案詳情可直接改進度與狀態。
  - 可匯出 Excel，也可下載匯入範本。
- **公司知識庫**：公司資料與知識條目，有關鍵字搜尋與可取消的分類篩選；選「內部敏感」或「客戶機密」時會提示只存摘要。
- **筆記**：三個資料夾。「管理層週報」和「外部情報摘要」由員工寫入；「知識庫素材」由實習生放訪談紀錄、SOP、案例、提案範本。
- **員工**：三位員工的排程、職責與最近產出，以及「問公司知識顧問」問答框。

## 資料保護

- 專案與請款（含金額）放在 `projects`、`invoices`，存取規則限定 Contributor 以上才能讀寫；只能檢視的人看不到金額。
- 每次匯入或修改後，頁面會另外寫一份不含金額的摘要 `shared/briefing`：只有專案名稱、進度、請款進度百分比、狀態、到期日，以及每期應收日與是否已收清。
- 週報彙整員和知識顧問只讀這份摘要；三位員工的指示都明確禁止讀 `projects` 與 `invoices`。
- 「問公司知識顧問」只送出：公開與內部一般的知識庫全文、敏感與機密條目的名稱和索引，以及不含金額的摘要。

需要注意：Artifact 的資料存放在 claude.ai，並非公司自有主機；員工與問答由 Claude 執行。內部敏感與客戶機密的全文不要放進平台（規格本來就要求只存索引）。

## 三位員工（Claude Routines）

| 員工 | 排程（台北時間） | 產出 |
|---|---|---|
| 外部情報摘要員 | 每週一 09:00 | 「外部情報摘要」筆記，每則附發布日期與網址 |
| 公司知識顧問 | 每週一 08:00 | 把「知識庫素材」整理進知識庫，並留一篇整理紀錄 |
| 管理層週報彙整員 | 每週五 17:00 | 「管理層週報」筆記，並寄到使用者本人信箱 |

完整指示在 `platform/routines/`。要修改排程或指示，請到 claude.ai 的 Routines 頁面。

**待處理：** 週報彙整員要寄信，需要 Gmail 連接器。這個組織不允許從對話中替排程任務附加連接器，請到 claude.ai 的 Routines 頁面，替「管理層週報彙整員」加上 Gmail。沒加之前，週報仍會寫進「管理層週報」筆記，只是不會寄出。

## 開發

```
node --test tests/*.test.js   # 計算規則與搜尋的驗收測試
node platform/build.js        # 產生 platform/dist/decision-platform.html
```

- `platform/lib/calc.js`：面板計算、匯入與不含金額的摘要，全部是固定公式。
- `platform/lib/kb.js`：知識庫欄位、搜尋與篩選。
- `platform/ui.js`、`platform/page.html`：畫面。
- 改完重新 build，再用 Claude 把 `platform/dist/decision-platform.html` 發布到同一個 Artifact 網址。

## 與原始規格的差異

- 「已結案」的專案不會出現合約到期警示，免得一直掛在清單上。
- 匯出的 Excel 會先經過瀏覽器確認再存檔，週報不附 Excel；金額請在平台上看。
- 「問公司知識顧問」用 Claude 回答，但只拿得到非金額、非機密的資料。

## 需向公司確認的問題

1. 專案清單與請款紀錄目前從哪個系統匯出？欄位名稱是否固定？
2. 客戶代號的編碼規則為何？是否需要一份只有內部看得到的對照表？
3. 合約到期日以合約迄日為準，還是以驗收日為準？
4. 逾期應收從應收日起算，還是請款日加固定天數？
5. 請款進度落後 20 個百分點才警示，這個門檻是否符合公司實際？
6. 週報目前只寄給使用者本人，執行長與主管是否需要直接收到？若要，需先確認寄送名單與個資處理。
7. 知識庫可收錄的資料範圍與四級資料定義，需請法務確認後再放內部敏感與客戶機密內容。【待法務確認】
