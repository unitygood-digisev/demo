# 管理層決策總覽系統

優樂地永續服務股份有限公司：只給執行長與主管用的決策總覽。它只回答三件事：這週先處理哪個專案、先催哪筆款、哪個約要續，以及回答問題時能不能引用公司自己的知識。

這個 repo 收的是不用連網就能跑的部分：兩個工具，以及 CubeLV 平台上員工、資料夾與藍圖的規格。平台上的空間、部門、資料夾、員工與排程，要在 CubeLV 裡建立（見下方「CubeLV 施工清單」）。

## 目錄

| 路徑 | 內容 |
|---|---|
| `mgmt-dashboard/` | 管理層總覽面板：匯入 Excel／CSV、四個總覽數字、警示、專案詳情、匯出 Excel |
| `knowledge-base/` | 公司知識庫：公司資料與知識條目、關鍵字搜尋、分類 chips、敏感等級提示 |
| `shared/style.css` | 兩個工具共用樣式（支援深色模式、手機寬度） |
| `cubelv/agents/` | 三位員工的排程與職責全文 |
| `cubelv/system-flow.json` | 系統藍圖（SYSTEM_FLOW，12 個節點、17 條邊，節點先標 `virtual`） |
| `cubelv/first-run/` | 第一棒產出：週報固定版型與資料需求、公司資料種子清單 |
| `tests/` | 計算規則與搜尋的驗收測試 |

## 使用方式

直接用瀏覽器開 `mgmt-dashboard/index.html` 或 `knowledge-base/index.html`，不需要安裝或伺服器。

- 資料只存在這台電腦這個瀏覽器（localStorage）。換電腦、換瀏覽器、清除網站資料後看不到；要留存請用面板的「匯出 Excel」。
- 兩個工具都沒有 callPrompt、fetchExternal 或任何外部請求；頁面用 CSP `connect-src 'none'` 擋掉連線。Excel 讀寫用的 SheetJS 0.18.5 放在 `mgmt-dashboard/vendor/`，不從網路載入。
- CSV 請存成 UTF-8（Excel「另存新檔」選「CSV UTF-8」），Big5 編碼的 CSV 中文會變亂碼；.xlsx 沒有這個問題。

### 管理層總覽面板

1. 按「匯入 Excel／CSV」，選「專案清單」，選檔；確認欄位對映與前 5 筆預覽後匯入。
2. 再選「請款紀錄」匯入。對不到專案時會先建立專案，之後匯入專案清單會補上合約資料。
3. 專案以合約編號為鍵、請款以「專案名稱＋期別」為鍵，重複匯入只會更新，不會重複。
4. 點警示或專案看詳情，可直接改進度與狀態。
5. 「匯出 Excel」產生 `mgmt-overview_YYYYMMDD.xlsx`，內含總覽、專案明細、請款紀錄、警示四張表，供週報附件。

計算規則全部是固定公式，見 `mgmt-dashboard/calc.js`；警示依嚴重度排序：應收逾期、合約已到期（0）→ 合約即將到期 ≤ 90 天（1）→ 請款落後 ≥ 20 個百分點（2）。

### 公司知識庫

「新增公司資料」或「新增知識條目」；資料等級選「內部敏感」或「客戶機密」時，表單會提示只存摘要與索取方式（只提示，不阻擋）。搜尋比對名稱、摘要、全文、標籤與內容；chips 再按一次即取消。

## 驗收結果

```
node --test tests/*.test.js
```

10 項測試全過。另用瀏覽器實測（2 個專案、3 筆請款，其中一列故意填錯）：

- 四個總覽數字：合約總額 NT$ 1,700,000、累計已請款 NT$ 900,000、未收款 NT$ 250,000、逾期應收 NT$ 150,000，與手算一致。
- 應收日昨天的未收款項出現在「應收逾期」；60 天內到期出現在「合約即將到期」；進度 80%／請款 50% 出現在「請款落後」。
- 錯誤列顯示「缺少合約編號；合約總額「abc」不是數字」。
- 重複匯入：新增 0、更新 2 個專案與 3 筆請款，沒有重複。
- 匯出的 Excel 可讀回，含四張表。
- 知識庫：新增兩筆、關鍵字搜尋、chips 切換與取消、敏感等級提示皆正常。
- 兩個工具全程外部請求數為 0；手機寬度 390px 沒有橫向捲動。

## 與規格的差異

- 「合約已到期／即將到期」不對狀態為「已結案」的專案示警，避免結案專案永遠掛在警示清單。若管理層要看，改 `calc.js` 中 `p.status !== '已結案'` 這個條件即可。
- 匯出檔名用英數字（`mgmt-overview_…`），避免部分瀏覽器把中文檔名換成「download」。
- 規格中由平台提供的儲存（MGMT_FOLDER、KNOWLEDGE_FOLDER 資料型別）在這裡用瀏覽器 localStorage 代替。上 CubeLV 時，欄位名稱與型別照規格不變，計算邏輯（`calc.js`、`kb.js`）可以直接沿用。

## CubeLV 施工清單（需在平台上執行）

這個工作環境沒有 CubeLV 的工具，以下沒有建立，要在平台上做：

1. 讀 `/app/config/skills/forge-plugin/SKILL.md`，插件照鐵律流程鍛造。
2. 建立 SPACE「管理層決策」、AICOMPANY_FOLDER「管理層決策小組」、NOTE_FOLDER「管理層週報」「外部情報摘要」「知識庫素材」，全部收進空間。
3. 依 `cubelv/agents/` 建立三位員工（parents 掛部門 id），把資料夾佔位換成真實 id。
4. 鍛造並發布兩個插件（可沿用本 repo 的計算、搜尋邏輯與畫面），用 vault_assign_space 收進空間；把插件連結補進員工職責。
5. 觸發三位員工的第一棒。週報版型與種子清單已備好在 `cubelv/first-run/`；第一篇外部情報摘要需由情報摘要員在平台上實際搜尋產出。
6. 用 send_message_to_session 通知員工工具已上線。
7. 依 `cubelv/system-flow.json` 建立藍圖，填真實 itemId 並清除 constructionState。

## 需向公司確認的問題

1. 專案清單與請款紀錄目前從哪個系統匯出？欄位名稱是否固定？
2. 客戶代號的編碼規則為何？是否需要一份只有內部看得到的對照表？
3. 合約到期日以合約迄日為準，還是以驗收日為準？
4. 逾期應收從應收日起算，還是請款日加固定天數？
5. 請款進度落後 20 個百分點才警示，這個門檻是否符合公司實際？
6. 週報目前只寄給實習生，執行長與主管是否需要直接收到？若要，需先確認寄送名單與個資處理。
7. 公司知識庫可收錄的資料範圍與四級資料定義，需請法務確認後再放內部敏感與客戶機密內容。【待法務確認】
